## Current Request Path For gptassistant

1. frontend loads `GET /api/gpts/detail/gptassistant`
2. frontend stores:
   - models
   - default model
   - default reasoning
   - upload file types
3. upload goes to `/api/upload` with current `model_id`
4. send-message goes to `/api/chat`
5. `/api/chat` receives:
   - `query`
   - `conversation_id`
   - `file_ids`
   - `base_model`
   - `reasoning_enabled`
6. `chat_routes.py` resolves selected `gptassistant.models[]` entry
7. `chat_service.py -> chat_with_gpt(...)` handles:
   - document extraction
   - image split / fallback extraction
   - execution path selection

Important: current `reasoning_enabled` is only wired at application logic level. It is not yet passed as a vendor-specific low-level model API parameter.

## Important Boundaries

- `chat_with_gpt(...)` is a `gptassistant`-specific orchestration layer, not a shared convergence point for all assistants.
- other assistants like `g3`, `g5`, `g6` still use `/api/{gid}/chat-messages`
- shared lower-level execution points are still:
  - `chat_with_react_as_function_call`
  - `chat_with_agent`
  - underlying `client.chat.completions.create(...)`

## Design Conclusions Reached In This Session

1. Backend should not infer reasoning content from raw `content` unless the upstream protocol explicitly provides a reasoning channel.
2. For OpenAI-compatible chat-completions, reasoning text and final answer text both arrive via `delta.content`.
3. Tool calls arrive via `delta.tool_calls`.
4. Frontend should likely own any reclassification or restyling of mixed reasoning/answer text.
5. `gptassistant` model definitions should live outside `model_tool.py`.
6. Assistant-level upload capability and model-level native-image capability should be separated.

## Known Open Questions

1. Final event protocol names and payload shapes are not settled.
2. `tool_call_delta` should probably be replaced or redefined.
3. Whether `reasoning_enabled` should become a real low-level provider parameter is still unresolved.
4. Whether `gptassistant` should converge on one execution path instead of switching between `chat_with_react_as_function_call` and `chat_with_agent` is still unresolved.
