ChatGemini / AI 助手规划架构图

统一主助手体验，兼容资料库、知识库、RAG、工具与沙箱能力

这张图不是“当前代码实现细节图”，而是面向未来 3-6 个月的目标架构。核心思想是： 主助手负责统一入口和主链路，资料库作为通用文件资产底座，知识库/RAG 作为资料库上的增强能力，其他同事的能力都按层接入，而不是直接打散到核心链路里。

主助手核心 可协作扩展层 基础设施与治理

L1 统一入口与产品体验层

所有渠道统一收敛到主助手，保持会话、权限、资料引用、工具使用体验一致。

Core Experience

Web 主端

当前主阵地，承载聊天、资料库、知识库入口、工具使用和灰度试验。

企业微信 / IM

适合轻交互、通知、快捷问答，核心能力仍由主助手统一编排。

其他内部系统入口

通过嵌入页、跳转页、组件化入口接入，不单独复制核心逻辑。

统一交互壳

负责会话框架、用户身份、权限上下文、统一菜单、消息输入区和结果展示框架。

讲法：无论入口在哪里，用户都应该感知为“同一个 AI 助手”，而不是多个各自为政的小工具。

L2 会话与上下文编排层

把消息、文件、知识库、工具、身份和任务状态绑定到一次完整的助手交互里。

Core Workflow

会话上下文管理

维护 session、消息历史、用户选择的文件/知识库、当前任务状态和多轮对话记忆。

Agent / 工作流编排

根据用户意图决定是否调用模型、知识库、业务工具、沙箱或多模态解析能力。

结果回传与呈现

把编排结果回到统一聊天体验中，而不是散落在多个孤立页面里。

讲法：这一层是主链路，不建议多人直接分散改动；扩展能力优先通过标准接口挂进来。

L3 资料库 / 文件资产底座

这是你规划中的关键底座，不只服务文档问答，还服务多模态理解、沙箱输入输出和后续生成资产沉淀。

Shared Asset Base

文件接入

  • 上传文件
  • 会话文件
  • 最近使用
  • 历史资产

对象存储

  • MinIO / OSS
  • 原始文件保存
  • 衍生文件保存
  • 版本与生命周期

元数据与权限

  • 文件类型
  • 标签 / 归属
  • 会话关联
  • 用户 / 组织权限

统一资料操作

  • 选中文件参与聊天
  • 查看详情
  • 加入知识库
  • 作为工具 / 沙箱输入
讲法：资料库是通用文件资产中心，知识库只是它的一种增强组织方式，不应该反过来吞掉整个文件体系。

L4 文件理解与处理管道

不同类型的文件按统一管道进入后续能力层，这里很适合多人并行建设。

Extension Zone

文档解析

PDF、Word、TXT、Markdown 等文本型文档提取。

图片理解 / OCR

图片问答、表格截图、扫描件识别、视觉摘要。

表格解析

Excel、CSV 数据结构化、字段识别、分析前置处理。

ZIP / 代码包解析

解压、目录结构识别、代码包说明、项目级问答入口。

音视频处理

转写、摘要、问答，作为后续可扩展能力预留。

沙箱文件 I/O

脚本运行输入、运行输出、结果文件沉淀回资料库。

讲法：这里是天然的分工区域，别人可以做具体处理能力，但不需要直接改主助手主链路。

L5 知识库与 RAG 增强层

把 A 的能力放在合理位置上: 它很重要，但它是资料库上的增强能力，不是整个文件体系的上位概念。

Knowledge Augmentation

知识库空间

知识库创建、命名、归属、成员管理和权限控制。

文件入库

从资料库选择文件加入知识库，而不是重新发明一套独立文件体系。

索引与切片

Chunk、Embedding、索引状态、增量更新、重建策略。

RAG 检索与问答

适合长期沉淀、跨文档问答、知识场景增强，是主助手的一种能力源。

讲法：这样定义以后，A 的知识库能力被抬到了平台能力层，但不会压住图片、ZIP、沙箱、表格等更广义的资料能力。

L6 业务工具与外部系统接入层

其他同事最适合切入的位置之一，能力可以快速扩展，又不直接破坏主助手架构。

Tool Integrations

OA / 内部系统

审批、流程、单据、组织信息、业务数据查询。

企业搜索

检索组织内站点、文档、公告、人员、流程资料。

业务 API 工具

统一定义工具协议，供 Agent 编排调用。

沙箱执行环境

代码执行、数据处理、文件转换、报表生成等需要运行时能力的场景。

讲法：工具是能力供给，主助手负责调度；工具本身可以由不同同事负责，各自独立演进。

L7 模型网关与治理层

真正的核心基础设施层，承载稳定性、审计、安全和成本治理，不适合被各方随意打穿。

Infra & Governance

模型网关

  • 模型路由
  • 多模型切换
  • 多模态能力选择
  • 统一调用协议

安全与审计

  • 鉴权
  • 权限校验
  • 操作审计
  • 敏感数据边界

稳定性与成本治理

  • 限流 / 熔断
  • 日志 / Trace
  • 反馈 / 评测
  • 调用成本观测
讲法：这一层决定线上可控性，所以多人协作可以补能力，但核心网关和治理边界必须统一收口。

建议你的定位

  • 主助手统一体验负责人
  • 资料库底座负责人
  • 会话与编排主链路负责人

建议 A 的定位

  • 知识库能力负责人
  • RAG 索引与检索负责人
  • 知识库内部交互与接口负责人

其他同事的切入点

  • 业务工具接入
  • 解析能力扩展
  • 企业微信 / 多入口接入
  • 评测、监控、运营治理
你在会上可以用一句话收口： “我们不是把所有能力都塞进知识库，而是先做统一资料底座，再把知识库、RAG、工具、沙箱、多模态能力按层挂上去。这样既能兼容大家的方向，也能保证线上主助手的体验和稳定性。”
